# C 语言学习路径

C 语言的价值在于它让内存、指针和生命周期这些"底层事实"变得可见。
本目录的笔记以"读懂机制 + 能跑通示例"为标准，不以背语法点为目标：
能预测一段代码输出什么、能解释它为什么这样输出，才算真的掌握。

| 顺序 | 文章 | 先修 | 学习目标与自测 |

| 1 | [[c-language-basics\|C 语言核心语法与指针实战]] | 会写变量、循环、函数 | 能解释指针步长、数组退化、`const` 与指针的三种组合；能写出不越界的字符串处理代码 |

## 环境与验证方式

- 示例统一使用 C23 编译：`cc -std=c23 -Wall -Wextra -Wpedantic`。
  若本机编译器较旧，退到 `-std=c17` 也能编译绝大多数示例（只有 `[[fallthrough]]` 需要 C23）。
- 每个示例都是完整程序，可单独保存为 `demo.c` 编译运行；不要把它们合并成一个文件，
  多个 `main` 会冲突。
- 建议额外用 `-fsanitize=address,undefined` 跑一遍：越界写和未定义行为会直接报出来，
  比事后调试快得多。

## 遇到问题先看哪一节

| 你遇到的现象 | 大概率是 | 该看的部分 |
|--------------|----------|------------|
| 程序直接崩溃，没有任何提示 | 空指针解引用、数组越界、栈溢出 | 指针 / 常见错误与排错 |
| 输出多了一行或少了输入 | 输入缓冲区里残留 `'\n'` | `getchar` 与输入缓冲区 |
| `sizeof` 算出的长度不对 | 数组名传进函数后退化成了指针 | 数组参数会退化为指针 |
| 想改字符串却被编译器或运行时拦住 | 字符串字面量位于只读段 | 字符数组与字符串的区别 |
| 结构体大小比成员之和还大 | 内存对齐产生的填充 | 内存对齐与 `sizeof` |
| 声明读不懂（一堆 `*` 和括号） | `()`/`[]` 优先级高于 `*` | 复杂声明 |

## 复习建议

1. 先通读一遍，不必记住语法细节，只建立"哪些机制和内存有关"的地图。
2. 把每个示例亲手敲一遍并改动参数，重点观察指针地址和 `sizeof` 的变化。
3. 合上笔记，用一张纸写出"字符串、结构体、函数指针"三者的声明与访问方式，再对照检查。
4. 做一遍常见错误表：每条都想想触发它的最小代码长什么样。

## 后续可扩展的主题

当前笔记覆盖语言核心，以下内容适合作为第二阶段：

- 动态内存进阶：`realloc`、柔性数组成员（flexible array member）、内存池
- 标准库深入：`<stdint.h>` 定宽类型、`<stdbool.h>`、`<stdatomic.h>` 原子操作
- 位运算与位域：标志位组合、协议字段解析
- 预处理：条件编译、`#include` 守卫、宏的常见陷阱
- 调试与观测：`gdb`/`lldb` 断点、`valgrind`、sanitizer 组合使用
- 构建与工程化：多文件编译、静态库与动态库、`Makefile`/`CMake` 入门
